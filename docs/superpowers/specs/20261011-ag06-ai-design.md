## 目标与边界

- HUI-1682：场景内轻文案（回复 / 邮件 / 营销简介）通过**正式 provider**（平台 task API → xingmo）生成候选正文。模型只产出候选，不写草稿、不发送、不发布、不记营销许可。
- HUI-1688：接待 AI 回复在有 FAQ 依据时，可由真实文本模型润色为正文；未通过依据校验则保留 FAQ 原文。模型不可用时文本降级。
- 不做：CRM 内建视频 / 数字人 / 产品图引擎；不新建 LLM 网关或钱包；不改 AG01 的模型供给与额度；不扩展到 Motion / Matrix（AG06-HANDOFF）。

## 决定与理由

D1 provider 与能力名。沿用现有 `PLATFORM_TASK_BASE_URL / TOKEN / ACCOUNT_ID` 三键，不新增环境变量。轻文案用 capability `text.generate`，接待沿用 `reception.phrase`。理由：public-ai `XingmoProvider` 的 MaaS 适配器只读取 params 中的 `prompt` / `input` / `text` 或 `messages`，而现行 leads 客户端发的是 `body`，真实调用会送出空提示词。因此两个能力的 params 都改为 `prompt`。

D2 输出读取。模型正文从 task 摘要的 `result_json` 读取，形如 `{"text":"..."}`，与 MaaS 适配器写入的结构一致。`result_json` 不是合法 JSON 或缺 `text` 时视为无正文；SUCCEEDED 但无正文仍按已计费（task 已执行）记 `recorded`，正文降级。

D3 计费语义。沿用 hold 0.01 元（1 分）。只有 SUCCEEDED 且带 task_id 才记 `recorded`。超时、UNKNOWN、FAILED、CANCELED 一律 `not_completed`，不双扣、不盲重提（同 idempotency key 由平台回放）。

D4 超时。接待路径保持 2 秒（访客等待）。轻文案生成用 30 秒上限，轮询退避 50ms → 500ms 上限，避免长轮询打满请求。

D5 `model_ready` 语义。`model_ready = 三键齐全`（已配置）。响应另带 `model_verified: false`，并在 note 中写明「已配置不等于已验证」。这样不伪造「真实模型可用」，同时前端能显示生成入口。真实验证结果只能来自真实 provider 运行，本轮不具备。

D6 轻文案生成不写草稿。生成结果存入新表 `light_copy_generations`（候选正文 + task 回执 + 状态），响应返回 `candidate`。草稿表 `light_copy_drafts` 的 CHECK 约束（origin='manual'、generated=0、live_charge=0）保持不变。采用候选 = 调用既有 PUT 保存为人工草稿。理由：模型只拟稿，人工保存才是采用；不覆盖人工改稿。

D7 轻文案事实输入。仅经 `lightcopy.Project` 投影所选事实（title / activity_ref / price_cents，价格需未过期证明）。联系人全文、内部备注、profile、授权快照一律不进入 prompt（Project 已拒绝）。prompt 不含访客文本。

D8 轻文案依据校验。候选正文中出现的每个阿拉伯数字串必须出现在所选事实拼接文本中；否则 `model_ungrounded`，不存候选、返回 409。占位符（`{{`、`}}`、`模板占位`）同样拒绝。长度上限 600 字符。

D9 接待依据校验（HUI-1688）。模型正文通过校验才替换 FAQ 原文，条件：非空、≤400 字符、无占位符、数字串均出现在 FAQ 答案中、承诺类词（保证、包退、退款、免费、承诺、最低价、绝对、一定）若出现则 FAQ 答案中也必须出现。任何不通过都保留 FAQ 原文，citation 不变。

D10 幂等。轻文案 idempotency key = `lc:<subject_kind>:<subject_id>:<kind>:<sha256(facts 与 body 指纹)>`，同内容重复点击返回同一平台 task，不新增费用。接待沿用 `sessionID:clientMsgID`。

D11 功能开关与默认。`FEATURE_LIGHT_COPY` 与 `FEATURE_RECEPTION` 默认仍为 off。未配置 provider 时，轻文案生成保持原 409 `model_unavailable`，已有测试不变。

D12 不把 provider 通过当成产品证据。fixture（httptest 模拟 public-ai 提交/轮询）只证明契约与降级，不是真实模型、不是计费通过、不是人工采用。

## 组件与接口

platformtask（server/internal/platformtask）
- `PhraseResult` 增加 `Text string`。
- 新增 `TextInput{IdempotencyKey, Capability, Prompt string, Language string}`、`TextResult{TaskID, Text string, CostCents int, BillingVerdict string}`。
- `(*Client).Text(ctx, TextInput) TextResult`：提交 `text.generate`（或指定能力），轮询，解析 `result_json.text`。
- `(*Client).WithTimeout(d time.Duration) *Client`：返回带新 HTTP 超时的副本。
- 轮询退避：间隔从 50ms 起翻倍，封顶 500ms。

lightcopy（server/internal/lightcopy）
- `OriginModel = "model"`（仅用于候选 DTO，不入草稿表）。
- `CheckGroundedNumbers(candidate, grounding string) string`：返回空串或 `ReasonUngrounded`。
- `ReasonUngrounded = "model_ungrounded"`，`ReasonModelFailed = "model_failed"`，`ReasonModelUnknown = "model_unknown"`。

store（server/internal/store）
- 迁移 0029：`light_copy_generations(id, tenant_id, subject_kind, subject_id, kind, candidate_body, task_id, cost_cents, billing_verdict, status, reason, created_by, created_at)`；CHECK：billing_verdict IN ('recorded','not_completed')，status IN ('proposed','failed','unknown','refused')，cost_cents IN (0,1)，UNIQUE(tenant_id, idempotency_key)。
- `InsertLightGeneration`、`GetLightGenerationByKey`。

reception（server/internal/reception）
- `GroundedReplyText(candidate, faqAnswer string) (string, bool)`：返回修剪后的正文与是否通过。

httpapi（server/internal/httpapi）
- `Server.LightWriter`（接口 `Text(ctx, platformtask.TextInput) platformtask.TextResult`）。`nil` 时轻文案生成走原 409 路径。
- `handleLightCapability` 输出 `model_ready`、`model_verified:false`、`live_charge:0`、tools、note。
- `handleLightGenerate`：校验 kind 与 facts；若 writer 为 nil，返回原 409；否则构造 prompt、调用 writer、按结果返回 `candidate` 或 409（model_failed / model_unknown / model_ungrounded），并写 generation 回执。
- `phraseReception` 返回 `(store.ReceptionModelCall, string)`，第二个值为可用正文（未通过则为空，调用方保留 FAQ 原文）。

config / server.Open
- 三键齐全时，同一 platformtask 客户端分别作为 `ReceptionPhraser` 与 `LightWriter`（后者 `WithTimeout(30s)`）。

## 数据流

轻文案：`POST .../light-copy/{kind}/generate` → 读草稿与所选事实（Project）→ 生成 prompt → `LightWriter.Text` → 依据校验 → 写 generation 回执（候选或失败）→ 返回候选（不改草稿）。
接待：访客消息 → Compose（FAQ 依据）→ phraseReception（prompt 含 FAQ 答案，不含访客文本）→ 依据校验 → 回复正文（模型或 FAQ）→ 既有发送 / 批准 / 人工接管逻辑不变。

## 错误处理

- provider 未配置：轻文案 409 model_unavailable；接待不调用模型，verdict not_completed。
- 提交失败、HTTP 非 2xx、超时：verdict not_completed；轻文案 409 model_failed；接待文本降级。
- 轮询中超时：task_id 可能存在，verdict not_completed，轻文案 409 model_unknown 并返回 task_id（不重提）。
- 候选不通过依据：轻文案 409 model_ungrounded，不存候选正文，但回执记录 status=refused 与 reason（不存模型原文以外的内容）。接待降级保留 FAQ。
